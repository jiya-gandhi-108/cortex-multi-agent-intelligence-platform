# Deploying Cortex

Production layout, all on free tiers:

```
browser ──▶ Vercel (Next.js, BFF proxy) ──X-Proxy-Secret──▶ Render (FastAPI + LangGraph, Docker)
                                                              ├──▶ Supabase Postgres (session pooler)
                                                              ├──▶ Render Key Value (Redis-compatible)
                                                              ├──▶ Groq · Tavily (outbound HTTPS)
                                                              └──▶ LangSmith (traces, optional)
```

The browser only ever talks to Vercel. The session token lives in an httpOnly cookie on
the Vercel domain, and the Vercel route handlers forward calls to Render with the proxy
shared secret, so the backend can trust the forwarded client IP for rate limiting.

Order matters: database first, then backend, then frontend, then wire the two together.

## What you need

| Account | Used for | Free-tier limit that matters |
|---|---|---|
| GitHub | Source, CI, Render and Vercel deploy hooks | — |
| Supabase | Postgres | Pauses after a stretch of inactivity; 500 MB |
| Render | API container and Key Value | Spins down after 15 min idle; ~1 min cold start; Key Value has no persistence |
| Vercel | Frontend | Function duration 300 s (affects live streams, see below) |
| Groq | LLM | `gpt-oss-120b`: 8K tokens/min, 200K tokens/day |
| Tavily | Web search | 1,000 credits/month |
| LangSmith | Tracing (optional) | Monthly trace allowance on the free plan |

Generate one secret now and keep it in a password manager; Render and Vercel both need it:

```bash
openssl rand -base64 48 | tr -d '\n=/+' ; echo      # PROXY_SHARED_SECRET
```

## 1. Push the repository

```bash
cd cortex
git remote add origin git@github.com:<you>/cortex.git
git push -u origin main
```

CI (`.github/workflows/ci.yml`) runs on the push: lint, migrations, tests with a coverage
gate, dependency audits, the offline evaluation, the backend image build and the
frontend build. Wait for it to go green before deploying.

## 2. Supabase (Postgres)

1. Create a project. Pick the region closest to your Render region (the blueprint uses
   Oregon, so a US West region). Save the database password.
2. **Connect** (top bar) → **Session pooler** → copy the URI. It looks like
   `postgresql://postgres.<ref>:<password>@aws-<n>-<region>.pooler.supabase.com:5432/postgres`.
   - Use the session pooler, not "Direct connection": the direct host is IPv6-only and
     Render cannot reach it. Transaction mode (port 6543) also works; Cortex disables
     prepared statements for that reason, and the test suite runs through a
     transaction-mode pooler.
   - If the password contains `@ : / ? # %`, URL-encode it (`python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1],safe=''))" 'p@ss'`).
3. You do not run migrations by hand: the backend container runs `alembic upgrade head`
   on every start, and LangGraph creates its checkpoint tables on first boot.
4. Data API: Cortex does not use it. Every table gets row level security with no
   policies, so the public `anon` key can read nothing. You can also switch the Data API
   off under **Project Settings → Data API**.

## 3. Render (backend + Key Value)

1. Render dashboard → **New → Blueprint** → select the repo. Render reads `render.yaml`
   and proposes `cortex-api` (Docker web service) and `cortex-redis` (Key Value).
2. It prompts for the `sync: false` values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Supabase session pooler URI from step 2 |
   | `PROXY_SHARED_SECRET` | The secret you generated |
   | `CORS_ORIGINS` | Your Vercel URL, e.g. `https://cortex-<you>.vercel.app` (you can fill this after step 4; the browser never calls Render directly, so a placeholder is harmless) |
   | `GROQ_API_KEY` | From console.groq.com → API Keys |
   | `TAVILY_API_KEY` | From app.tavily.com |
   | `LANGSMITH_API_KEY` | From smith.langchain.com → Settings → API Keys (leave empty to disable tracing) |
   | `LLM_PRICING_JSON` | `{"openai/gpt-oss-120b":{"input":0,"output":0},"openai/gpt-oss-20b":{"input":0,"output":0}}` on Groq's free plan. To see what runs would cost on the paid tier, use the per-1M-token prices from groq.com/pricing instead |

   `JWT_SECRET_KEY` is generated by Render; `REDIS_URL` is wired from `cortex-redis`.
3. **Apply**. The first build takes several minutes (WeasyPrint system libraries).
4. When it is live, open `https://cortex-api-<suffix>.onrender.com/health/ready`. Expected:
   `{"status":"ready","checks":{"database":"ok","redis":"ok"}}`. Render uses the same
   endpoint as its health check, so a deploy with a broken database URL never goes live.
5. If you left `LANGSMITH_API_KEY` empty, set `LANGSMITH_TRACING` to `false` too.

If startup fails, **Logs** shows the reason. Common ones:
`password authentication failed` (wrong password or unencoded special character),
`Network is unreachable` (you used the direct IPv6 host), or
`JWT_SECRET_KEY must be set` (the generated value was removed).

## 4. Vercel (frontend)

1. vercel.com → **Add New → Project** → import the repo.
2. **Root Directory**: `frontend`. Framework preset: Next.js (auto-detected). Leave build
   and output settings at their defaults.
3. Environment variables (Production and Preview):

   | Variable | Value |
   |---|---|
   | `BACKEND_URL` | `https://cortex-api-<suffix>.onrender.com` (no trailing slash) |
   | `PROXY_SHARED_SECRET` | The same secret as on Render |

4. **Deploy**. Then copy the production URL back into Render's `CORS_ORIGINS` (Render
   redeploys automatically when an environment variable changes).

## 5. Verify the deployment

From your machine, with the backend virtualenv (or any Python with `httpx`):

```bash
cd backend && uv sync && cd ..
backend/.venv/bin/python scripts/smoke_deployed.py https://cortex-<you>.vercel.app \
    --api https://cortex-api-<suffix>.onrender.com
```

This checks health, security headers, the auth gate, registration through the frontend,
cookie flags (HttpOnly, Secure, SameSite), cross-origin write rejection, that the backend
sees your Groq key, that live event streams open through the proxy, logout and
server-side token revocation. It creates one throwaway `smoke-…@example.com` account.

Add `--full` to also run one quick research end to end and download the PDF. This spends
real Groq tokens and a few Tavily credits (one search per research task).

Then sign in through the browser and run a project yourself.

## 6. LangSmith (optional)

With `LANGSMITH_API_KEY` set and `LANGSMITH_TRACING=true`, each run appears in the
`cortex` project at smith.langchain.com as one trace: graph nodes, every Groq call with
token counts, and search and fetch tool spans. Secrets are never put in trace metadata.

## 7. Live evaluation (optional)

The benchmark suite in live mode runs real research for each benchmark and stores results
in the production database. Run it from your machine against the Supabase URL; do not
run it on Render's free instance.

```bash
cd backend
DATABASE_URL='<session pooler URI>' GROQ_API_KEY=... TAVILY_API_KEY=... \
  .venv/bin/python -m app.evaluation run --mode live --depth quick --limit 3
```

On Groq's free plan 200K tokens/day covers only a few benchmarks per day; use `--limit`
and spread runs out.

## Free-tier behaviour to expect

- **Cold starts.** After 15 minutes without traffic Render stops the backend; the next
  request waits about a minute. The first page load after a quiet period is slow, not
  broken.
- **Runs cut by spin-down or redeploys.** A run in progress when the instance stops is
  marked *interrupted* on next start, and **Resume** continues from the last LangGraph
  checkpoint in Postgres, so finished agent work is not repeated. To avoid spin-down,
  set the repository variable `KEEPALIVE_URL` to `https://cortex-api-<suffix>.onrender.com/health`;
  `.github/workflows/keepalive.yml` then pings every 10 minutes. One always-on service
  fits in Render's 750 free hours a month. GitHub may delay scheduled workflows, so this
  reduces spin-downs rather than guaranteeing none.
- **Live view reconnects.** Vercel ends a function after 300 s, so a live event stream
  longer than that is cut. The browser reconnects automatically with `Last-Event-ID` and
  the backend replays missed events from Redis, so nothing is lost; you may see the
  status flicker to "connecting" for a moment.
- **Key Value has no persistence.** A Render Key Value restart drops event streams,
  rate-limit counters and the logout revocation list. Projects, reports and checkpoints
  live in Postgres and are unaffected. A token revoked before such a restart becomes
  valid again until it expires (60 minutes by default).
- **Groq daily tokens.** A run may use up to its token budget (120K by default,
  `MAX_TOKENS_PER_PROJECT`); the free plan's 200K tokens/day on `gpt-oss-120b` therefore
  allows only a few runs a day. Quick depth uses far less. When the daily
  limit is hit, Groq returns 429 and the run fails with a rate-limit message. Groq's
  Developer plan (pay as you go) lifts this.
- **Supabase pausing.** A free project that sees no activity for a while is paused;
  restore it from the dashboard and restart the Render service.

## Updating

Push to `main`. Render redeploys the backend (migrations run on start) and Vercel
redeploys the frontend. Run `scripts/smoke_deployed.py` afterwards.

## Rolling back

Render: **Events → Rollback** on a previous deploy. Vercel: **Deployments → Promote to
Production** on a previous deploy. Migrations are additive in this release; if you ever
need to reverse one, run `alembic downgrade -1` locally against the database URL before
rolling back the code.
